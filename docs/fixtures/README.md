# 合成夹具

本地开发和 core 测试只用合成数据。这里的标识都是编出来的。不要放入真实学生的姓名、学号、照片或答卷。

## 最小结构

一份夹具有六块：

| 块 | 内容 |
| --- | --- |
| question | 题目版本标识、学科、题干、是否已核准 |
| answer | 答案版本标识、答案文本、是否已核准 |
| student | 合成学生标识。卷面不印姓名，所以没有姓名 |
| paper | 一次发给该学生的卷。题目版本、答案版本、题序、素材和版面是发卷时要冻结的标识 |
| pending_answer | 服务端装载的待确认作答。它绑在这一份卷、这一道小问和这一次复核版本上，状态是待确认 |
| photo_version | 照片版本。这一段只有页标识和版本号，没有图片字节 |

## 示例

[rational-number-min.json](rational-number-min.json) 是一道有理数运算的最小夹具。标识与 core 测试里的合成数据一致：`q-v1`、`a-v1`、`student-synth`、`teacher-synth`。

再做一份时，复制这个文件，只改合成标识，六块都保留。不要粘贴真实照片的 base64，也不要填真实姓名。

这份文件不启动服务，也不写入数据库。出卷用例冻结的是题目版本和答案版本；测试里的内存快照可以沿用同一组标识。

本机 HTTP 启动时读取这份文件，但把题目和答案先放成未核准，等老师在页面上核准并发布。另授一名合成学生 `student-synth-2`，只为打出第二张卷。这名学生不是第七块，文件仍是上面的六块。卷面打印合成学号，不打印姓名。

`pending_answer.text` 是学生写下的合成作答，和 `answer.text` 不是同一句。出卷时页面展示这句作答。每一份卷仍使用自己的作答编号。
