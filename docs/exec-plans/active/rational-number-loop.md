## 要证明的事

在浏览器里，老师可以核验并发布一道题，给一名学生生成一份卷，打开 PDF，并确认一条作答记录。服务端拒绝未核准题目的正式出卷。相同确认再提交一次不产生第二条记录。这一段不包含手机拍照。

本地开发使用合成题目、合成学生和假适配器。这不代替真实学生试用前的运行时安全验证，也不代替数据库和文件在同一恢复点的联合恢复。

## M1 契约

下面四项是这一段的执行契约。服务端和网页技术栈已由 ADR 0012 采纳。FastAPI 和 React 已锁版本。PostgreSQL 这一步不连接。机构还没确认的地方标为待确认。预期结果是做出来之后必须能观察到的事。

### 发卷时冻结什么

冻结的是这一次发卷用到的：题目版本、适用答案版本、素材标识、版面。素材标识包括原图和题目图的文件标识。版面包括题序、页码、学号的位置和模板标识。卷面不印姓名。

旧 PDF 用发卷时写下的文件标识取回，不按后来的题库重新渲染。标识还在、字节却变了，就视为取回失败，并留下原来的标识。

可观察到：改题库之后，旧卷上的版本标识和文件标识不变；用旧标识读到的字节仍是发卷时那一份。

待确认：产品最终用哪个程序渲染 PDF。ADR 0012 没有选定。本轮合成样张用标准库写一页 Helvetica PDF，用来核对公式、页码和合成学号，不安装 reportlab 或 WeasyPrint。这不表示机构已经选定渲染程序。

已测量的选项：标准库单页可以在浏览器里显示 `(-3)+5`、页码和合成学号，中文题干留在网页上。reportlab 加中文字体、WeasyPrint 都还没装。

2026-11-16 评审修复：学生卷不再画答案和解析。发卷时把公式文本和版本标识一起冻结。修改题干或答案生成未核准的新版本，原版本和核准记录保留；新版本核准后才能出新卷。先出待渲染卷、再改题库、最后渲染时，旧卷仍用冻结的公式。样张用标准库 Helvetica，覆盖 Latin-1，包括 `2×3`。超出 Latin-1 时返回稳定的 `not_rendered`，卷留在待渲染，页面给出原因。中文题干仍在网页上。产品渲染程序仍待确认。

2026-11-16 收尾复验：同一原版本的两条修订各自得到不同的未核准版本，已完成的停用不会被旧的发布快照写回。样张改用 WinAnsi，`2×3` 的乘号在查看器里可见；字体画不出的字符仍留在待渲染。作答查询按当前卷、小问和复核版本读取。作答文字来自夹具里的 `pending_answer.text`，不是标准答案。启动探针确认本次进程已绑定、健康接口可访问，并且进程活到冒烟结束。

2026-11-16 合入前两项：正式发放的响应只写回发起它的那一代卷面。切到另一张卷之后，晚到的成功或失败不改当前卷号、作答、确认、同键重试和提示。启动探针在同一个就绪时限内继续等待本次进程绑定和健康响应；进程提前退出就失败，别人占用的端口不被动。

2026-11-17 出卷与发放重叠：出卷还没结束时，旧卷的正式发放和确认先关掉。晚到的发放成功或失败只在卷号仍是当前卷时写回页面；已经落到服务端的发放留在那张卷的列表行上。当前打开的卷、作答、提示、确认和同键重试保持同一张卷。就绪总预算同时限制健康检查的连接和正文读取。正文分段返回且整段超过预算时，探针记就绪失败，并停掉这次拉起的进程。

2026-11-17 旧列表与分块健康：发放成功之后，后到的旧列表不能把该卷改回可打印。新列表里其他卷的字段仍采用新快照，列表里已经没有的卷不补回来。出卷期间仍不能发放或确认旧卷。晚到的另一张卷的错误不写进当前卷。健康探针只请求 http。预算内的分块正文和 Content-Length 正文都能判为健康；分段间隔短、总时长超过预算时仍是就绪失败。判定耗时和进程清理耗时分开记。

发卷时先查题目和答案都已核准、题目未停用。请求里的学科必须等于题库记录里的学科，老师身份必须等于服务端这次确定的老师。学生卷上写下的是题库里的学科、服务端老师、题目版本、答案版本、题序、素材和版面。

状态只按下面的条件变：

| 状态 | 进入条件 | 失败时 |
| --- | --- | --- |
| 待渲染 | 发卷成功。还没有文件标识 | 未核准、已停用、学科不符、无权限时不写卷 |
| 可打印 | 已经有文件标识和校验值。渲染程序仍待确认，本轮只检查这两个值在不在 | 缺标识或校验值时留在待渲染 |
| 已发放 | 当前是可打印，而且相关发布记录这时还没停用 | 发布记录已停用时不发放，原来的文件标识留着 |
| 取回旧 PDF | 用卷上的文件标识和校验值 | 标识还在但校验值变了，视为失败，旧标识不换 |

### 确认的操作键

操作键的幂等范围是这一次确认：学生卷、小问、服务端确认的老师、操作键字符串。同一个字符串用在另一张卷、另一个小问或另一位老师上，是另一次确认。复核版本不放进这个范围，另外核对。版本变了就拒绝，即使操作键是新的。正式记录的冲突仍按学生卷、小问、复核版本判断。

| 情况 | 结果 |
| --- | --- |
| 同一范围，内容相同 | 返回原来的确认记录，不写第二条 |
| 同一范围，内容不同 | 拒绝 |
| 同一老师把同一个操作键字符串用在两张卷上 | 各自成功，两条正式记录 |
| 同一老师把同一个操作键字符串用在同一张卷的两个小问上 | 各自成功，两条正式记录 |
| 两个不同的键，或两个老师（即使键字符串相同），同时确认同一小问的同一复核版本 | 一个成功。另一个得到槽位冲突。正式记录仍是一条 |
| 同一键、同一内容并发重试 | 两边都得到原来的那一个确认 ID。正式记录仍是一条 |
| 复核版本已经变了，而这是第一次确认 | 拒绝，不写记录 |
| 已经成功的确认，和复核版本更新同时发生 | 重放仍返回原来的确认。版本更新不改那条记录 |
| 作答不属于这张卷、这道小问、这次复核，或不是待确认 | 拒绝，不写记录 |
| 决定不是采纳、修改或驳回 | 拒绝。已有的正式记录保持原样 |
| 无权限再提交同一键 | 拒绝，不把原来的确认 ID 交出去 |

待确认：操作键的具体字符串由谁生成。方案 1.1 第 10.2 节只把它写成输入，没有定格式。网页把老师提交的字符串原样送上，示例是 `key-web-1`。这不表示生成方已经选定。

### 没有上传时的待确认作答

这一段不拍照、不上传。合成夹具提供一条已经绑在该学生卷和小问上的待确认作答。内容是合成文本，或一个标明为夹具的页标识。里面没有真实学号、姓名或学生照片。

建议若要出现，只来自假适配器的固定输出，并且输出标明是假的。不调用真实模型。

可观察到：老师确认这条夹具之后，出现一条正式记录。相同操作键再提交一次，正式记录仍是一条。

### 四个端口各管什么

| 端口 | 负责 | 不负责 |
| --- | --- | --- |
| catalog | 题目版本和适用答案版本是否都已核准，以及发布记录里的版本标识和素材标识 | 不保存学生卷，不写出卷结论 |
| practice | 学生卷、发卷时冻结的引用、确认记录、操作键的重放和冲突。未核准时拒绝正式出卷 | 不改题目正文 |
| PDF 渲染 | 按已冻结的版本和版面生成字节，并返回文件标识。失败时卷留在待渲染 | 不决定能否出卷。渲染程序待确认 |
| 授权 | 这一次请求的老师是否可以处理这个学生和这门学科。拒绝时 practice 不写卷，也不写确认 | M1 用内存假规则。真实分工等 DEC-02，待确认 |

## 步骤

1. 选定本切片的语言和工程文件。若选定，先写新的 ADR 取代 ADR 0010 里的对应句子，并补上锁文件。未选定时停在这一步问用户，不并行开两套框架。

3. 只在 `catalog` 和 `practice` 实现 R1、R2、R3、R5 的最小规则。授权用 practice 里的内存端口，不先建 `identity` 目录。
4. core 测试用假端口。至少覆盖：未核准出卷被拒绝；确认后正式记录出现；相同操作键重放返回原结果；不同内容的同一操作键被拒绝。
5. 组合根 `backend/bootstrap/compose.py` 只做装配。日志适配器写标准输出 JSON。故意制造一次确认失败，用 request_id 在输出里找到 ERROR。
6. 一条命令能把这个用例跑起来。把 `scripts/check.conf` 的 `SERVICE_CMD` 设成那条启动命令，把 `BUSINESS_TEST_CMD` 设成最小业务冒烟，并写进 README。文档冒烟可以留下。`TEST_KIND` 保持 `docs`，直到 `TEST_CMD` 本身就是 core 测试。依赖清单在这次改动里：`APP_DIRS` 是 `. apps/web`，`INSTALL_CMD` 安装锁定的 Python 依赖并执行 `npm ci` 后构建页面。`requirements.txt` 每行用 `==`。网页锁文件是 `apps/web/package-lock.json`。
7. 网页在老师这台电脑的浏览器里能核验、能打开 PDF。到这里第一段结束。
8. 下一段再做安卓拍照、上传和缺页。网页和安卓都走完之前，不宣称 AC-06 通过。
9. 桌面壳排在网页已经顺畅之后。第一段不安装 Tauri 或 Electron。
