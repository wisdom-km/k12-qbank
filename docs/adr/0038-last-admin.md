# ADR 0038 至少一个活跃管理员

状态：accepted

## 背景

库里可以有多名 `admin`。若一次停用或改角色之后不再有活跃管理员，就没有人能创建老师或恢复账号。`disable_teacher` 今天只接受 `role=teacher`，目标不是老师时返回 `not_found`。

## 选项

1. 允许停用最后一名管理员，再靠环境变量重新引导。引导在已有管理员时不会再生效。
2. 留下不变量：活跃管理员不能被减到 0。`disable_teacher` 继续不能用于管理员。

## 决定

选 2。

- 活跃管理员是 `role=admin` 且 `status=active` 的用户。
- 领域函数 `ensure_last_admin` 只在 `disable_user` 和 `change_role` 这两类操作上检查。操作完成后活跃管理员数量会变成 0 时，返回 `Err("last_admin")`，并且不写状态。
- 重置口令的失败不触发这个检查。`disable_teacher` 不改成能停用管理员，也不把「目标不是老师」改成 `last_admin`。
- `change_role` 还没有路由。函数先落在领域里，供以后的角色变更使用。

## 后果

最后一名活跃管理员不能被停用，也不能被改成老师。要减少管理员，必须先有另一名活跃管理员。

## 状态

采纳。2026-11-18。
