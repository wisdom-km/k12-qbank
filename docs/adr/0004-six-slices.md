# ADR 0004 六个深模块

## 背景

变化通常来自：题怎么发布、知识点怎么归属、谁能看学情、一次练习怎么确认、模型怎么建议、纸卷和文件怎么呈现。这些不该拆成「每个按钮一个模块」。

## 选项

1. 按数据库表拆模块。
2. 按一次请求的执行步骤拆模块（先识别、再保存、再显示）。
3. 按一起变化的业务决策切六块，每块隐藏自己的状态规则。

## 决定

选 3。

| 切片 | 隐藏的决定 | 公开能力 |
| --- | --- | --- |
| catalog | 题目版本、答案版本、是否可正式使用 | 查询已核准快照，发布或停用 |
| knowledge | 章节树和知识点不是同一件事 | 按标识查询知识点 |
| identity | 老师、学生、学科负责关系 | 回答能否访问这名学生的这个学科 |
| practice | 卷次、页、作答、确认和更正 | 创建练习、接收页、确认作答、查历史 |
| analysis | 模型差异、任务和证据 | 提出建议和候选题，不写老师结论 |
| delivery | 排版和导出 | 读取已授权数据并生成 PDF |

知识点卡片、PPT、家长报告以后做自己的呈现，不反过来决定题目是否合格。不建 `utils`、`helpers`、`common`。

## 后果

一个改动应落在一个切片。跨切片只传普通数据和标识。第一段代码只建 `catalog` 和 `practice`。授权先放在 practice 的内存端口里。`knowledge`、`identity`、`analysis`、`delivery` 等有代码再创建目录。新代码必须放进这六块之一，或放进 kernel / 组合根，不能另起一套名字。

## 状态

采纳。2026-11-14。
