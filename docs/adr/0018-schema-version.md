# ADR 0018 按契约版本分发草稿

## 背景

ADR 0017 用 JSON Schema 检查字段形状。两份契约都已经写了 `$id`。草稿文件只有 `contract_version`。以后若同时存在第 2 版，解析器无法只靠文件名决定该用哪一份形状。

## 选项

1. 继续只认文件名。版本不同时，错误仍是某个字段不符合第 1 版。
2. 契约文件写明 `version`。草稿文件写明 `schema_version`。解析按 `$id` 和这个版本选择形状。对不上的版本直接拒绝，并写出收到的版本。

## 决定

选 2。

- 两份契约文件顶部保留 `$id`，并增加整数 `version`。第 1 版的值是 `1`。这是契约自己的标记，不是草稿里的字段。
- 题目草稿和答案草稿增加整数 `schema_version`。第 1 版必须是 `1`。`contract_version` 仍保留。
- `parse_question_draft` 和 `parse_answer_draft` 先按 `$id` 与 `schema_version` 选择契约。未知版本、布尔值，或没有该字段，失败码仍是 `not_draft`。说明是「收到的版本是 …」，并带上实际收到的值。
- 不是对象的内容仍交给形状检查。整页 OCR 块列表因此仍会指出类型，而不是被说成缺版本。
- 不新增包。不连接 PostgreSQL。核对页的复制件要与这两份文件一致，由核对页仓库的同步检查负责。

## 后果

旧的草稿文件没有 `schema_version`，导入会被拒绝。核对页要在下一次保存时写出这个字段。ADR 0014 列出的答案文件键补上 `schema_version`。

## 状态

采纳。2026-11-17。补充 ADR 0017，不取代 ADR 0013 或 ADR 0014。
