# ADR 0024 中文用本机楷体

状态：accepted

## 背景

ADR 0022 记下 Noto Sans CJK 的许可证是 SIL Open Font License 1.1，不在 MIT、BSD、Apache-2.0 里，并停在等人决定。那一条正文不改。

用户选定楷体，也可以用标准常用的字或微软黑体。本机字体目录里对应的是楷体、微软雅黑和黑体。这三份不作为新包放进仓库。

## 选项

1. 接受 OFL，把 Noto 放进仓库。
2. 生成这一页时读本机字体目录。先用楷体，没有再用微软雅黑，再没有用黑体。只嵌入这一页用到的字形。字体文件不进仓库，嵌了字形的样张也不进仓库。
3. 继续让中文留在待渲染。

## 决定

选 2。文件顺序是 `simkai.ttf`、`msyh.ttc`、`simhei.ttf`。读到的路径必须落在 `%WINDIR%\Fonts` 里。

拉丁字符，包括乘号，仍用 Helvetica 和 WinAnsi。根号这类不在中日韩范围里、WinAnsi 也写不出的字符，仍返回 `not_rendered`，原因句不改。

不新增包。不加入 reportlab 或 WeasyPrint。

机器上没有这三份字体时，中文仍不生成 PDF。干净环境的检查机就是这样。

## 后果

公式里出现中日韩统一表意文字、中日韩标点或全角字符时走这条路径。题干里冒号前面的汉字仍不进卷面，公式仍取冒号后面的一段。

不把字体文件放进仓库，也不把嵌了字形的样张提交进仓库。

## 状态

采纳。2026-11-18。用户选定楷体，可用微软雅黑或黑体。不把字体文件放进仓库。不取代「拉丁字符用 Helvetica」。

## 修订（2026-11-24，R4b）

卷面改印完整题干和选择题的全部选项。汉字不再为了绕开字体而留在练习项里。字体由部署环境提供，查找顺序是 `K12_PDF_FONT_PATH`、Linux 上的 Noto CJK 常见路径、Windows 上的微软雅黑或宋体。字体文件仍不进仓库。

缺字体时显式报错：`K12_ENV=production` 启动退出；development 出卷返回 `pdf_font_missing`。任何环境都不许只印公式、丢掉汉字。

拉丁字符仍用 Helvetica。根号这类写不出的字符仍是 `not_rendered`。

部署环境给出的字体如果是 CFF（`fonts-noto-cjk` 的 OpenType 集合就是这种），同样只嵌入这一页的字形轮廓，不整包嵌入，也不改成只写 ToUnicode。

## 修订（2026-11-24，R4e）

卷面公式按排版印出，不印 LaTeX 源码。数字和字母仍用 Helvetica。运算符和公式里的中文走部署环境的中文字体。缺字形仍是 `not_rendered`。见 ADR 0046。
