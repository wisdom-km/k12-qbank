# ADR 0001 按长期项目做

## 背景

要决定这是做完就扔的原型、留下骨架的曳光弹，还是会演进的长期项目。方案 1.1 写的是机构试点，并要扩展到整册、多册和其他学科。

## 选项

1. 原型：验证完就扔。README 标明会扔掉。
2. 曳光弹：只留下一条最薄的真实路径当骨架，文档从简。
3. 长期项目：先定依赖方向、端口、不变量和给 AI 的约束，再按切片长大。第一条可运行路径仍然要薄。

## 决定

选 3。长期信号已经成立：要保存学生、作答和作业照片；老师会访问；寿命按数月以上演进；多个 agent 会改同一仓库；有隐私和授权。因此不按原型做。

第一条可运行增量仍是有理数运算的一条教学闭环，做法上用曳光弹的厚度，架构上用长期项目的规则。

本次写文档时，用户没有另说「长期」或「曳光弹」这三个字。档位是按方案 1.1 里的信号定的，不是口头点选。若要改档，需要用户明确说。

## 后果

开工门按长期，并且 [D] 是、[P] 是。文档用全套。硬规则要有机器检查或标明 review。未测量的时间、准确率和容量不写死。

## 状态

采纳。2026-11-14。
