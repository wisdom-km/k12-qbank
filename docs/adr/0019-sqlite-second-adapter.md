# ADR 0019 SQLite 能不能当第二个适配器

状态：accepted

## 背景

有一项要求给 catalog 或 practice 的某个端口加第二个适配器，用标准库 SQLite 写真实的行，并和内存适配器跑同一套契约测试。不新增包。

ADR 0012 已经把关系数据库产品定为 PostgreSQL。这一段还没有连接，也没有迁移。第一次把一行写入 PostgreSQL 时，同一改动里要有可回退的迁移，并且只建这次有行要写的表。空表不算落地。

SQLite 会是第一次把行写进一个数据库文件。这和「产品是 PostgreSQL，第一次写入走 PostgreSQL 迁移」碰在一起。

## 选项

1. 先写一个 SQLite 文件适配器。它真的写行。契约测试和内存适配器一起跑。PostgreSQL 仍是产品，SQLite 只作过渡，以后删掉。
2. 不做 SQLite。第二个适配器等 PostgreSQL 和可回退迁移一起出现。在那之前，持久适配器仍是无。

## 决定

选 2。数据库产品仍是 PostgreSQL。不做 SQLite 过渡适配器。第二个会写行的适配器等到第一次 PostgreSQL 写入，同一改动里带可回退的迁移，并且只建这次有行要写的表。不改 ADR 0012。

没有 SQLite 文件，没有数据库驱动，没有迁移，没有空表。

## 后果

实现矩阵里的持久适配器保持「无」，直到第一次 PostgreSQL 写入。契约测试仍只跑内存适配器。

## 状态

采纳。2026-11-18。用户选定等到 PostgreSQL。不取代 ADR 0012。
