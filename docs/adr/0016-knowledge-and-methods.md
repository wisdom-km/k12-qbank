# ADR 0016 知识点和解题方法入库，错因只作建议

## 背景

题目行不放知识点名称。知识点已经是单独的表，见 ADR 0015。老师还要知道这道题用哪种做法，例如移项、通分。学生做错之后，要能指出这次漏了哪个知识点、哪种做法。

这些名字如果每次由模型现编，同一种做法会出现不同措辞，以后无法统计同一个孩子反复错在哪里。模型建议在老师确认之前也不是正式结论，见 ADR 0005 和 PRD 的 R3。

这一段仍不连接 PostgreSQL，也不加迁移。数据库仍是 ADR 0012 的那一个 PostgreSQL。老师仍在同一个网页里核题、维护目录和看建议。

## 选项

1. 知识点、解题方法和这次错因都放进题目行，或都由模型现场生成，不留目录。
2. 知识点和解题方法各自成目录，连到题目版本。某一次做错只生成建议，建议指向目录里的标识。老师确认后，才成为这一次的错因。

## 决定

选 2。

- 知识点仍按 ADR 0015：`knowledge_point` 和 `question_knowledge`。一道题可以有多条。最多一个 `primary`。综合练习是 `support`。没有标签的题可以保存和核准，但不出现在按知识点的检索里。
- 解题方法是另一张目录，不并进知识点，也不写进题目行。它回答「怎么做」。知识点回答「要懂什么」。
- 某一次作答的错因不是题目的属性，也不是参考答案。它不写入 `question_version`，不写入 `answer_version`。学生写的内容仍留在 practice 的作答。
- 模型只生成建议。建议引用这道题已经挂上的 `knowledge_point_id` 和 `method_id`，并带证据。确认、改判或手评之后，才成为这一次的正式错因。
- 模型说出目录里没有的名字时，这段文字留在建议上。分析用例不得因此插入 `knowledge_point` 或 `method`。老师决定是否把这个名字加进目录，并改到对应标识。
- 建议不是发布记录，也不能把题目标成已核准。

| 表 | 何时建 | 列 |
| --- | --- | --- |
| method | 第一次保存一种解题方法 | `method_id`、`subject_id`、显示名 |
| question_method | 第一次把一种做法挂到题目版本 | `question_version_id`、`method_id`。一道题可以有多条。不设主次 |
| 建议上的引用 | 第一次保存一条待复核建议 | 已有的 `knowledge_point_id`、`method_id`。目录外的名字只作建议上的文字 |

`knowledge_point` 和 `question_knowledge` 的列仍以 ADR 0015 为准。没有要写入的行时，不建这些表。

## 后果

连库时先读 ADR 0012、0015 和本条。只建这次真正要插入的表。检索和错因统计使用目录标识，不使用模型当次生成的自由文字。换模型供应商不改变这些表。

## 状态

采纳。2026-11-17。不取代 ADR 0005 或 ADR 0015。补上解题方法的列，以及错因与目录的边界。
