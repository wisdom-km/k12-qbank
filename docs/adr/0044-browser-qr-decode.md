# ADR 0044 二维码在浏览器里读

状态：accepted

## 背景

ADR 0041 把收卷照片定为 purpose `intake`，并按「卷 + 页」定位。有码时要读出卷号和页码。读不出，或这张卷出卷时没有印码，老师当场手选。

服务端如果自己解码，就要加图片库。手机拍的原图还带 GPS 等拍摄信息。老师在读不出码的时候，需要立刻看到「未识别」，而不是等上传失败。

## 选项

1. 服务端用 Pillow 加 zbar，或用 OpenCV 读码。照片原样上传，服务端再缩小、再去掉拍摄信息。
2. 老师手机的网页用前端库 jsQR 读码。上传前在浏览器里把长边缩到不超过 3000 像素，重新编码成 JPEG。服务端不信任网页报上来的卷号和页码，逐项再核对。后端不加图片库，也不加 multipart 依赖。

## 决定

选 2。

- 读码库是 jsQR 1.4.0，许可证 Apache-2.0，没有运行依赖。网页把它钉在 `apps/web/package.json`。
- 浏览器先用 `createImageBitmap` 按拍摄方向摆正，再用 canvas 缩小，然后交给 jsQR。整张读不出时，再把右上角放大后读一次。二维码印在页眉右上角。
- 重新编码成 JPEG（质量 0.85）会去掉 GPS 和其他拍摄信息。上传体是这张 JPEG 的原始字节，`Content-Type` 是 `image/jpeg` 或 `image/png`，不用 multipart。
- 服务端只把网页读到的原文当作待核对的字符串。`located_by=qr` 时，原文必须能按 `paperId#page` 解析，并且卷号和页码等于路径里的卷号和页码，否则 `qr_mismatch`。`located_by=manual` 不带原文。
- 服务端再核对卷存在、页码在 `1..page_count`、文件头魔数、大小不超过 `K12_INTAKE_MAX_BYTES`。JPEG 再用标准库去掉 APP1 和 APP13，存的是删过之后的字节。
- 只有这张卷的出卷老师和管理员能上传和读取。

## 没选的方案

服务端 Pillow + zbar，或 OpenCV。没选是因为那是新的 Python 依赖，而照片在上传前已经由浏览器缩小并重新编码。读不出码时，老师要在手机上立刻手选，不必先把整张原图传到服务端。

## 后果

按题裁切、用模型核对照片上的学号和页码，仍不在本条里。见 ADR 0041 第 6 条和 R6。
