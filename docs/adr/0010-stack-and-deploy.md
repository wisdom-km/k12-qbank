# ADR 0010 技术栈和试点部署未拍板

本条里「后端 Python」「网页 React 或 Vue」「关系数据库 PostgreSQL」这三句候选，已被 [ADR 0012](0012-adopt-stack.md) 取代：服务端定为 Python 3.12 与 FastAPI，网页定为 React，数据库产品定为 PostgreSQL。安卓界面（Flutter 或 React Native）、部署地点、模型供应商和备份数字仍以本条为准，0012 没有取代。

## 背景

方案 1.1 给了候选，并写明框架、供应商、机型、部署地点和备份数字都还没定。DEC-03、DEC-04 也还没由机构确认。

## 选项

1. 现在就把 FastAPI、PostgreSQL、React、Flutter 写成唯一选择，并规定服务跑在老师电脑的局域网上。
2. 先固定业务边界。技术栈保持候选。试点部署把「机构电脑 + 手机可访问的受控局域网」当作默认计划，等 DEC-04 再采纳或替换。

## 决定

选 2。

候选，不是决定：后端 Python；网页 React 或 Vue；安卓 Flutter 或 React Native；关系数据库 PostgreSQL；公式在网页上用 MathJax；文件先放本地目录，以后可以换对象存储。

已经决定的边界不受候选影响：模块化单体、R1–R6 在服务端、端口在供应商前面、网页和 App 共用用例、手机不能用电脑上的 localhost 当作自己的地址、不把服务无控制地公开到公网、首版不承诺离线。

模型供应商要等机构确认处理条件，并用获准样本比较。在此之前用假适配器做 core 测试。真实调用要有重试上限和费用上限。额度数字待定标。

## 后果

第一条编码任务开始前，若要选定其中一项，另写 ADR 把本条中的对应句子改为被取代。不要在代码里同时引入两套网页框架。

提议中的部署、安卓界面、供应商和备份数字仍有效。2026-11-14。
