# ADR 0011 网页和桌面用同一套界面

## 背景

老师要在浏览器里工作，也要有一个可安装的桌面端。方案 1.1 还要求可安装的安卓 App 负责拍照。框架版本、试用机型、安装渠道、部署地点、模型供应商、备份数字、姓名遮挡和按学科扩展的细权限，都还没有试用数据。ADR 0010 把这些留在候选里。

## 选项

1. 三套界面：浏览器用一种框架，桌面再写一套，安卓再写一套。
2. 一套 Flutter 同时做网页、Windows 桌面和安卓。
3. 老师的浏览器用一套网页。Windows 桌面安装这同一套网页，只加一个很薄的壳。安卓仍是单独的可安装拍照端，只调用同一个服务端用例。

## 决定

建议选 3。状态先保持提议。顺序是：先做浏览器里的网页。老师这台电脑上能核验题目、能打开带公式的 PDF 之后，再加桌面壳，然后再把本条改为采纳。

桌面壳如果要加，用系统里已经有的网页组件来包这同一套网页，优先试 Tauri 2 的稳定版。老师电脑配置不高，不把 Electron 当作退路：它会再带一个浏览器。Tauri 2 在这台 Windows 上打不开时，继续只用浏览器，不换 Electron。不用 Tauri 3 的 alpha。第一段代码不打包桌面。

网页界面先用 React 的当前稳定版，不并行引入 Vue。公式仍用 LaTeX 候选加 MathJax。具体版本以第一条切片的锁文件为准。2026-11-14 在公开发布页看到的候选是 React 19.3.1、Tauri 2.12.5。落地前再核对，不把这两个数写成已经装上。

安卓继续用 Flutter 的当前稳定版做可安装包，不把 Flutter 同时当成桌面和网页的第一选择。原因：老师长时间对照原图、改公式和打印，网页更合适；Flutter 若要取代这套网页，先用一页真题证明公式和打印，再另写 ADR。

其余项仍不拍板：

| 事项 | 建议的默认 | 什么时候改 |
| --- | --- | --- |
| 安卓机型 | 用老师实际那一台，不指定型号 | DEC-04 填了真机之后 |
| 安装渠道 | 签名的试用包直接安装，不上应用商店 | 机构要分发时再定 |
| 部署地点 | 机构电脑上的服务，桌面和手机走受控局域网 | 上云另写 ADR。桌面壳里的 localhost 不是手机的地址 |
| 模型供应商 | 不选。开发用假适配器 | DEC-03 确认后，用同一批获准样本比较，再写 ADR |
| 备份数字 | 不编。规则仍是数据库和文件同一恢复点 | 第一次演练记下用时和可丢失窗口 |
| 姓名遮挡 | 默认只传题目区域。整页和去不掉的手写姓名留在机构内，转老师处理 | 试用前由机构确认能接受的做法 |
| 学科权限 | 首版只做机构、学生、学科负责关系。多机构不做 | 第二门学科用真实题型和权限再验证，不预做空接口 |

服务端边界不变：模块化单体，R1 到 R6 只在用例里执行，网页、桌面壳和安卓都不写这些规则。

## 后果

浏览器和以后的桌面壳共用一套界面。安卓仍是第二套界面，排在网页之后，范围限在登录、拍照、上传、看建议和确认。第一段代码只做网页上的核验、出卷和确认，不建安卓工程，也不打包桌面。桌面壳真的要加时，再验证打印、选文件和更新。Tauri 的构建依赖 Rust，那一步失败就留在浏览器里。

版本号、供应商和备份数字在本条里没有被采纳。ADR 0010 仍然有效。
