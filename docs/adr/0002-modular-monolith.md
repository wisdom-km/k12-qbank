# ADR 0002 模块化单体

## 背景

网页、安卓和后台任务要共用同一套业务规则。以后可能换模型、加练习册、加学科。现在没有独立扩容的证据。

## 选项

1. 按表或按页面拆很多服务，用消息总线连接。
2. 一个部署单元，内部按业务切片分开，切片之间只走公开用例。
3. 一个大服务文件，按调用顺序往下写。

## 决定

选 2。一个后端进程加一个工作进程。切片是资料与题库、知识体系、身份与授权、练习与确认、分析与推荐、呈现与导出。

选 1 的时机写成触发条件，而不是现在就做：同一条需求反复跨很多切片改、某个切片要单独扩容、任务并发已经影响使用、并且先测量过瓶颈。在此之前不引入微服务和消息平台。

选 3 否决。按执行顺序切模块会把规则摊进页面和脚本。

## 后果

首版部署和排错更简单。切片边界错了要靠依赖检查发现，不能靠事后拆服务补救。性能数字待定标，不用 100 或 300 名学生推断容量。

## 状态

采纳。2026-11-14。
