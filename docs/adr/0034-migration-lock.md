# ADR 0034 迁移并发安全

状态：accepted

## 背景

两个进程可能同时执行 up 或 down。ADR 0029 的运行器按版本号应用 SQL，正文没有写并发。不改 ADR 0029 的正文，也不把 yoyo 加回来。

## 选项

1. 靠数据库之外的文件锁。
2. 用 PostgreSQL 的事务级咨询锁包住整次 up 或整次 down。

## 决定

选 2。

- 语句是 `SELECT pg_advisory_xact_lock(%s)`。键是参数，不拼进 SQL。
- 锁键是八字节 `k12mig01` 的大端有符号 int8：`7724010281418305585`。up 和 down 用同一键。
- 一次 up 或一次 down 放在同一个事务里。锁在事务开始时取得，提交或回滚时由数据库释放。
- 这个事务覆盖本次计划中的全部版本。某一个版本失败，则本次计划全部回滚。
- 两个连接并行 up 时，后一个等到前一个结束。两边都成功时，已应用版本集合相同。

## 后果

运行器要改成整次方向一个事务。已经合入的 `V001__init.sql` 文件不改。CI 仍对全部迁移做 up、down、up。

## 状态

采纳。2026-11-18。不改 ADR 0029 正文。
