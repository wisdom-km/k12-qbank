## 诉求

发布物能列出直接依赖的名称和版本。有一份 SBOM。不把这份清单写成已经审计通过。

## 当前实现

`.github/workflows/ci.yml` 的 check 作业第 74–82 行在临时虚拟环境安装 `cyclonedx-bom`，再对只装了 `requirements.txt` 的环境生成清单：

```yaml
"$RUNNER_TEMP/sbom-tool/bin/cyclonedx-py" environment \
  "$RUNNER_TEMP/app/bin/python" \
  --output-reproducible \
  --no-validate \
  --spec-version 1.6 \
  --output-format JSON \
  --output-file bom.json
```

第 84–90 行用 `actions/upload-artifact@v7` 上传 `bom.json`，`retention-days` 是 90，缺文件则该步失败。`cyclonedx-bom` 不写入 `requirements.txt`。

名称和版本的锁定来源是 `requirements.txt` 的 `==` 行。当前直接相关的两行是第 10 行 `fastapi==0.165.0` 和第 23 行 `starlette==1.10.0`。每次 CI 用当时的锁文件重新生成 `bom.json`，所以产物版本跟着锁文件，而不是跟一份旧表。

`docs/evidence/sbom-2026-11-22.md` 记录了这条 CI 路径和 90 天保留。该文件第 17–18 行的包表仍是升级前的 fastapi 0.115.6 和 starlette 0.41.3。那张表不是 `c62e439` 的当前版本。本页不改它，也不把它当作现在的 SBOM 内容。
