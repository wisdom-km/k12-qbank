# #32 速率限制

日期：2026-11-23。基线 `origin/main` `c62e439`。issue 创建于 2026-11-17T23:19:11Z，标题「速率限制」。本页按发布计划 Batch A 只记录现状。不给其余路由新编次数，不签 AC-07。

## 诉求

同一来源超过约定次数时拒绝，并留下不含学情正文的事件。次数若还没定，不编一个生产额度。

## 现状即满足的对应

机构没有另给一套全路由次数。代码里已经有两处窗口。本批记录这两处的数字和它们盖住的路径，不把数字改成新的生产额度，也不写成每条 API 都有窗。

登录窗在 `backend/identity/adapters/memory_rate_limiter.py` 第 1 行和第 14–18 行。默认是账号 5 次失败 / 15 分钟，IP 20 次 / 1 分钟。`backend/bootstrap/compose.py` 第 89–94 行用 `WindowLimiter(attempts, enabled=enabled)` 装进登录依赖。`K12_RATE_LIMIT_LOGIN` 不是 `0` 时启用。

`backend/identity/application/login.py` 第 20–28 行：先 `limiter.check(user_hash, ip_hash, now)`。被拒时 `hit` 记下哈希和原因码，审计的 `target_id` 是空字符串，运行日志是 `login_failed`。传入的是 `username_hash` 和 `ip_hash`，不是口令，也不是请求正文。`backend/identity/application/notes.py` 第 1 行写明审计和运行笔记不含口令和会话标识。第 38–48 行的 `runtime` 只发 `event` 和 `outcome`。

`tests/identity/test_limiter.py` 第 17–22 行：5 次失败后下一次检查是 `account_locked`。第 24–27 行：同一 IP 20 次之后是 `ip_throttled`。

就绪探针是另一处。`backend/bootstrap/ready.py` 第 13–19 行：同一 IP 60 秒 30 次。`backend/bootstrap/http_app.py` 第 56 行把 `ReadyWindow()` 放在应用上。`tests/test_health_ready.py` 第 75–86 行：第 31 次 `GET /health/ready` 为 429，`code` 和 `message` 都是 `ip_throttled`。响应里没有学情字段。

`http_gate.py` 的 `gate` 不调用 `WindowLimiter`。除登录和 `/health/ready` 以外的路由没有这两道窗。

## 不在本批

给其余路由加限额要先有机构给的次数。issue 禁止现编。发布计划把这一半列为延后。本页不写成全部 API 已限流。

## 结论

满足。范围限于登录窗和 `/health/ready` 的现状。AC-07 未签。其余路由的限额不在这次关闭所代表的行为里。
