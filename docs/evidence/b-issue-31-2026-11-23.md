# #31 请求体大小限制

日期：2026-11-23。基线 `origin/main` `c62e439`。issue 创建于 2026-11-17T23:19:09Z，标题「请求体大小限制」。本页按发布计划 Batch A 只记录现状。不改 `http_gate.py`，不新编机构额度，不签 AC-07。

## 诉求

超过约定上限的请求被拒绝，并且不把整段请求体写入日志。上限若机构还没定，实现时写「需要人工决定」，不编一个生产额度。

## 现状即满足的对应

机构没有另给一个生产额度。仓库里已经有一个代码常量，本批把它记下来，不把它改成新的数，也不把它说成机构已经拍板的额度。

`backend/bootstrap/http_gate.py` 第 16 行：

```python
_MAX_BODY = 1_048_576
```

第 60–68 行只在请求带了 `Content-Length` 时比较。没有这个头时返回假，闸门不拒绝：

```python
def _too_big(request: Request) -> bool:
    raw = request.headers.get("content-length")
    if raw is None:
        return False
    try:
        size = int(raw)
    except ValueError:
        return True
    return size > _MAX_BODY
```

第 25–26 行：判为过大时返回 `payload_too_large`。`backend/bootstrap/http_errors.py` 第 28 行把这个码映射到 413。第 34–43 行的响应体只有 `code`、`message`、`request_id`，没有请求正文。

`tests/test_http_session.py` 第 71–72 行：

```python
huge = client.post("/api/login", content=b"{}", headers={"Content-Length": "2000000"})
self.assertEqual(huge.status_code, 413)
```

访问日志在 `backend/bootstrap/http_app.py` 第 139–147 行。`http_completed` 记下路由模板、状态码和 `request_id`，参数里没有请求体。

因此：带 `Content-Length` 且大于 1048576 的请求会被拒绝，日志行里没有整段正文。这就是本批所说的「现状即满足」。

## 不在本批

没有 `Content-Length` 的请求不走第 60–68 行的比较。发布计划把「无长度头也拒绝」列为延后，那一步要改 `http_gate.py`。本批不改。本页不写成所有大请求都会被拒绝。

## 结论

满足。范围限于上面的现状。AC-07 未签。无长度头的半边不在这次关闭所代表的行为里，它留在发布计划的延后项，本批不新开 issue。
