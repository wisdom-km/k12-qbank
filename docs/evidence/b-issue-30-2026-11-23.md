# #30 CORS

日期：2026-11-23。基线 `origin/main` `c62e439`。issue 创建于 2026-11-17T23:19:06Z，标题「CORS」。2026-11-18 的评论写「本条仍未实现」，那是 ADR 0040 合入之前。本页记录合入后的代码。不改中间件，不签 AC-07，不代替 issue #2。

## 诉求

浏览器只接受明确列出的来源。不在名单里的来源要被拒绝。不要把任意来源和带凭证的请求配在一起。合成页面的本机来源不算本条通过。

## 当前实现

ADR 0040 状态是 accepted。决定写明 `allow_credentials` 为真，方法只有 `GET` 和 `POST`，`production` 没有来源就退出，名单里出现 `*` 也退出。

`backend/bootstrap/run_mode.py` 第 26–45 行：

```python
def cors_origins(env_raw: str, raw: str | None, logger: Logger) -> tuple[str, ...]:
    """development defaults to the local page. production refuses an empty list.

    An empty or missing value is not ``*``. A list that contains ``*`` is refused
    in both modes, because credentials are on.
    """
```

同文件第 35–36 行：`production` 且名单为空时 `_refuse(..., "cors_origins_required")`。第 43–44 行：任一条目是 `*` 时 `_refuse(..., "cors_origin_wildcard")`。`development` 的默认来源在第 23 行，只有 `http://127.0.0.1:5173` 和 `http://localhost:5173`。

中间件在 `backend/bootstrap/http_app.py` 第 177–185 行。`allow_credentials=True`，`allow_origins` 用上面函数的返回值，不写死 `*`。组合根在第 42–46 行先算来源，再装配应用。

`tests/test_http_cors.py`：

- 第 32–58 行 `test_cors_production_requires_origins_env`：`production` 缺名单时期望 `SystemExit` 码 1，日志 `outcome` 是 `cors_origins_required`，标准输出里没有 `*`。
- 第 60–68 行 `test_cors_production_rejects_unlisted_origin`：名单是 `https://teacher.example` 时，`https://other.example` 的响应没有 `access-control-allow-origin`；名单内来源带回显，并且 `access-control-allow-credentials` 为 `true`。
- 第 70–79 行 `test_cors_development_allows_localhost`：development 的两个本机来源有头，`https://other.example` 没有。这条只说明开发默认值，不算生产白名单通过。

字面量 `*` 的拒绝在 `run_mode.py` 第 43–44 行。`tests/test_http_cors.py` 没有单独把 `K12_CORS_ORIGINS=*` 送进 `cors_origins` 的用例。本页不把「测试文件的 docstring」写成那条用例已经存在。

满足。生产空名单和名单外的来源已有代码和测试，`*` 在代码里会拒绝启动。关闭本条不表示 AC-07 已签。
