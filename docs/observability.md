# 健康检查与错误上报

状态：设计加占位。仓库里还没有 HTTP 进程，所以还没有真实的 `GET /health`。M-14 要到发布前、服务真的能被访问时才算通过。这份占位不代替那次检查。

## 健康检查

有服务端之后，HTTP 入口提供 `GET /health`。

进程能应答时，正文只有：

```json
{"status": "ok"}
```

返回里不放密钥、连接串、数据库地址、学生标识、姓名或照片。

现在 `backend/bootstrap/health.py` 的 `health_report()` 返回这个固定状态。`compose()` 把它放进装配结果。没有路由，也不检查数据库。数据库出现之后，同一个接口再回答「必需依赖是否可连」。连不上就不是 `ok`。那一步再对真实进程写测试。

运行平台可以用这个接口决定要不要重启。返回里仍然不放内部细节。

## 错误上报

网页和以后的安卓客户端把错误发到我们自己的接口。老师在界面上看到错误编号。上报里带同一个编号，才能和日志对上。

最小字段：

| 字段 | 含义 |
| --- | --- |
| error_id | 界面上给老师看的错误编号 |
| request_id | 和服务端日志里的请求编号相同 |
| app_version | 客户端版本 |
| platform | `web` 或 `android` |
| error_code | 稳定错误码，不是堆栈原文 |

样例：

```json
{
  "error_id": "err-synth-1",
  "request_id": "req-synth-1",
  "app_version": "0.0.0",
  "platform": "web",
  "error_code": "store_failed"
}
```

不上报这些内容：学生照片、姓名、学号、整页或裁切后的图片、密钥、token、连接串、整段请求体、完整提示词。堆栈若要留下，先去掉这些内容。

还没有接收上报的接口。HTTP 进程出现时再加，并让字段扫描拒绝上面那些敏感名字。
