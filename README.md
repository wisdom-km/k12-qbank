# k12-qbank

[英文](README.en.md)

面向机构教师的初中数学练习与诊断系统。  
以结构化题库为基础、以课堂教学目标为起点、以学生作答证据为依据、以教师确认为教学结论准绳。

它不是单纯的 OCR 工具，也不是让大模型自由生成试卷的工具。主要价值是减少教师在题目整理、组卷、回收、初步分析和再练选题上的重复劳动，同时保留教师对教学内容和学生结论的控制权。

基线文档：2026-11-10《初中数学题库与教学系统需求与架构设计 V2.0》。  
当前仓库以架构约束、领域模型与检查脚本为主，教学服务尚未实现。

## 本系统重点解决的五个问题

| 问题 | V2.0 决策 |
|---|---|
| 课后作业如何对应“这节课讲了什么” | 新增课堂、班级和教学目标，将作业直接关联课堂及其目标快照 |
| 五个人做同一套题，个人重点如何体现 | 采用“共同必做题 + 个人重点关注 + 批改后巩固计划”三层机制 |
| AI 分析后如何自动形成下一套题 | 自动生成受约束的巩固计划草稿，从已核准题库选题，教师审核后发布 |
| 如何避免一道错题就给学生贴永久标签 | 新增学习证据和可修正的掌握状态，区分证据不足、待复核和已确认问题 |
| 如何看到五个学生的共性与差异 | 新增班级知识点、错因、题目和巩固效果视图，不只展示平均分 |

系统最重要的边界：**识别失败、证据缺失和学生不会，是三种不同状态。**

## 完整业务闭环

课堂与教学目标 → 共同作业与个人关注 → 纸笔或在线作答 → 照片回收与证据检查 → 识别、判分和错因建议 → 教师复核确认 → 学生反馈、订正与自我解释 → 学习证据与掌握状态 → 巩固计划草稿 → 教师审核并发布 → 再次练习与延迟复测 → 回流证据。  
同时支持班级共性与差异分析。

首版成功标准不是“识别了多少页”，而是能完成上述真实闭环（含五名学生共同作业 + 个人关注 + 不同巩固计划草稿）。

## 架构

首版采用**模块化单体**、PostgreSQL、受控文件存储、持久任务表和后台工作进程。网页与安卓 App 共用同一 HTTPS 业务入口。

主要模块及其职责：
- `classroom`：记录课堂、读取教学目标、登记教师观察
- `catalog`：检索可发布题、核验发布、取得核准快照、停用问题版本
- `practice`：创建作业、上传提交、确认作答、查询历史
- `analysis`：请求分析、读取建议、登记运行结果
- `remediation`：生成计划草稿、批准计划、记录效果
- `delivery`：生成纸卷或报告、取得授权下载
- `identity`：校验当前操作者对学生、班级、学科和资源的权限

关键原则：
- 原 PDF、页图、题目裁图和学生作答照片全程可追溯
- 题目与答案解析分别核验、分别版本化，核准后才能正式发布
- 同一套题发给多名学生时，每名学生有独立实例和历史快照
- AI 只产生建议，教师确认后才形成正式教学结论
- 已发作业、照片、建议与评价修订不可原地覆盖
- 权限、隐私、审计、费用控制、备份恢复从首版开始实施

详细分层与不变量见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 技术栈与部署（候选）

| 组件 | 候选方案 | 说明 |
|------|----------|------|
| 后端 | Python + FastAPI | 模块化单体 |
| 数据库 | PostgreSQL | 关系数据与事务约束 |
| 文件存储 | 本地目录 / 对象存储 | 不可变资产管理 |
| Web | React 或 Vue + MathJax | 复杂核验与复核优先 |
| Android | Flutter 或 React Native | 拍照上传与轻量确认 |
| AI | 多模态 / 语言模型适配器 | 分阶段、可弃判、可人工降级 |
| 部署 | 机构电脑 + 受控局域网 | 试点阶段 |

最终选型待试点数据与机构确认后记录为 ADR。详见 [docs/adr/](docs/adr/)。

首版先做 1–2 周纵向验证（核准题 → 建作业 → 上传 → 建议 → 教师确认），再根据结果估算完整 MVP 工期。不提前建设微服务。
